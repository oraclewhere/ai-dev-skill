# 队列

## 0. 两个队列

```
doc/待裁/           规则层：rule-manager 的核心轨裁决，人回来复核
  escal-0001.md
  索引.md           自动生成的汇总
doc/待批/           事项层：非核心轨待批项，人回来批
  appr-0001.md
  索引.md
```

**为什么每项一个文件 + 一个索引**：人批量审批需要索引，机器状态追踪需要单项文件。

## 1. 单项格式

```yaml
---
id: escal-0003
type: "第三方依赖版本冲突"          # 必须命中总授权的类型集合
paths: [code/order/, code/pay/]     # 必须是某总授权路径的前缀子集
based_on: "判据 D-0007 命中"
dissents:                           # 不可删除；没有写"无"
  - role: impl-worker
    text: "会影响 order 模块的同步库存扣减"
blast_radius: "task-0003 的 AC-3；触及 code/order/"
reversible_by: "branch task-0003（未合入）"
no_forecast_reason: "尽调时未拿到并发量数据"
default_if_unanswered: "不做"       # 保守默认，必填
anchor: "doc/交付件/del-0003.md"    # 事实锚点，必填
blocks: [task-0003#验收标准-3]      # 空 = 非核心轨
status: open                        # open / decided / defaulted
created: 2026-09-25
---
```

**两处必填，缺一律不许进队列**：

- `default_if_unanswered` —— 保守默认，且必须是"可逆的、不阻塞其他推进的"那一个
- `anchor` —— 事实锚点，必须是**已存在**的产物路径

理由：不设这两条，agent 有动机把所有事都列为"不确定"，
将来做错了可以说"我列过了，你没定"——**那是责任转移**。
保守默认让"列举疑问"的成本上升，事实锚点让它可被 hook 核查。

## 2. 状态机（极小）

```
open ──人裁定──→ decided        （记录人的原话）
  └──人说"剩下的全走默认"──→ defaulted   （走保守默认）
```

**没有别的状态。** 不加 `in_progress`、不加 `pending_review`——
每多一个状态就多一个"谁有权改它"的判断点。

## 3. 渲染（秘书）

人离线一段时间后回来看到 20 条散项会干脆不看。所以：

- **批次开头给一个数字** —— 队列长度 + "其中 N 项阻塞推进"
- **稳定 ID** —— 人才能说"批准 1、3、5"
- **分组** —— "其中 3 项同属认证模块，可以一起定"
- **排序** —— 按 `blocks` 引用的验收标准条数降序（**不是按"严重程度"**，那是判断）

每条呈现**必须齐**的信息：

```
[3] escal-0003 · 第三方依赖版本冲突 · 阻塞 1 条验收标准
    改动范围   code/order/, code/pay/
    依据       判据 D-0007 命中
    反对意见   1 份（impl-worker：会影响 order 模块的同步库存扣减）
    保守默认   不做（对该任务无阻塞）
    牵动       task-0003 的 AC-3
    → 通过 / 退回
```

**"反对意见"和"保守默认"不许省略。**
前者是人推翻裁决的主要依据；后者是人说"剩下的全走默认"时必须已有的事实。

## 4. 秘书的写权限，只有一处

> **记录人的裁定**：`status` + 人的**原话**。

- **队列项内容不得修改。** 一个"整理"动作就能悄悄改变人看到的材料，
  而人以为自己看的是原始事实。
- **不得代替人 `decided`。** 人没说就是没说。
- 人说了"剩下的全走默认" → 那些项记 `defaulted`，并记录这句原话。
- **不得给推荐。** 给"通过 / 退回"的选项是对的，给"我建议通过第 3 项"是错的。

## 5. 索引怎么生成

索引是从单项文件扫出来的，**不是手写的**。手写的索引会和单项漂移。

- 扫 `doc/待裁/*.md`、`doc/待批/*.md`（跳过 `索引.md` 与 `_模板.md`）
- 提取 `id / type / status / blocks 条数`
- 按 `status: open` 优先、`blocks` 条数降序排列

**索引里不写内容摘要。** 摘要是二次加工，会成为除单项文件之外的第二个"人看到的材料"来源。

## 6. 并发：必须加锁

**同一事件的多个 hook 是并行执行的**，写同一状态文件会有竞态。

- 队列落盘一律用 `flock`，或
- 一律采用**追加写**（一行一个 JSON）

不要"先读整个文件再改再写回"——那是最典型的丢更新场景。

## 7. 队列长度 = 人的回访信号

`status: open` 的条数，是"该回来看一眼了"的**客观**提示。

**它是提示，不是门槛。** 不阻塞任何东西。任何"积压到 N 条就停"的设计都是在
给团队加一个会把人锁回机器的门槛。

## 8. 离开声明时

需求分析师**产出**三档清单，秘书**呈现**并记录裁定。

分工不能混：需求分析师自己直接问人，它就成了第二个人机接口，
"审批类交互唯一入口是秘书"就破了。

人回来时按档分组，**突出"当前需要"档**（人只需处理这一档），
"预期"档给人一个选项：**现在就定 / 交给 rule-manager 到时候裁**（后者产生临时授权）。
